What leaves the browser, and what does not.

Last updated 12 October 2026.

This policy covers the GmailClass Chrome extension and the website at gmailclass.ticekralt.com. GmailClass collects limited event counts on the website and optional usage events from the extension as described below.

The extension

GmailClass classifies Gmail messages that are already loaded on screen. It adds its own category chips. It does not send, delete, archive, mark read, or apply Gmail labels.

Classification stays off until you save a TypeSafe API key, acknowledge the disclosure, and turn it on. A connection test uses a synthetic subject, not mail from the inbox.

What can be sent

When classification is enabled, list metadata and your category instructions are sent to TypeSafe at https://api.typesafe.ai/v1/systemone. For each loaded row, that can include:

  • Sender name and address, when Gmail shows them
  • Subject
  • The visible snippet
  • The displayed date
  • Your category descriptions and optional priority context

Message bodies and attachments are not read. Metadata can still be private. This is not local or anonymous inference. Requests go to TypeSafe with your own key.

Email text is sent as data. It is not rendered as HTML, and model output can only change the extension’s chips and its own interface.

What stays on this browser

The TypeSafe API key is stored in chrome.storage.local, with trusted-context access, so content scripts cannot read it. That storage is still part of the browser profile. It is not a hardware-backed encrypted vault. Replacing or removing the key clears the saved connection check. The old key is not written to logs.

Cached judgments store probabilities and ids, not message bodies. Overrides stay on this browser until you reset them or delete the category. Account scopes are SHA-256 hashes of the observed account email. Hashing is not encryption.

Permissions

  • storage — settings, cached judgments, and the API key
  • alarms — recover classification work after the service worker stops
  • https://mail.google.com/* — read the open message list and show chips
  • https://api.typesafe.ai/* — send list metadata for classification when you enable it

Optional extension analytics

Anonymous usage reporting is off by default. You can turn it on or off in extension settings independently of classification. After opt-in, the extension sends only a fixed event name when you first opt in, activate classification, add a category, or successfully use matching category chips. Label use is limited locally to one signal per browser per UTC day. Fixture/demo classifications are never reported.

These events never include email metadata, message or account identifiers, category names or descriptions, API keys, classification answers, or device identifiers. Small markers stay on your browser to prevent duplicate opt-in and daily label-use signals. Disabling reporting stops future events. Events are not queued for later delivery; failed deliveries are dropped.

The website host permission, https://gmailclass.ticekralt.com/*, allows these optional reports. No Gmail permissions are added.

This website

This site counts homepage views, visits with at least 15 seconds of visible activity, download button clicks, delivered extension ZIP downloads, demo-link clicks, example interactions, and TypeSafe link clicks. Page views include repeat visits; downloads are not proof of installation.

How analytics is stored

Reports go to our first-party analytics endpoint on Vercel. Only a UTC date, a fixed event name, and an aggregate count are saved in Neon Postgres, for up to 400 days, with older totals pruned on subsequent activity. The analytics database does not store IP addresses, user agents, URLs, referrers, precise event timestamps, cookies, visitor IDs, or event-level histories. Counts cannot identify unique people or connect website visits to extension activity. We do not sell analytics data or use it for advertising.

Website analytics uses no cookies or browser storage and respects Do Not Track and Global Privacy Control. Detectable automated requests are excluded. Our private analytics dashboard requires a password; its short-lived secure cookie is only for administrator authentication.

Vercel and Neon process network requests to operate these services and may keep their own operational logs, which can contain connection information such as IP addresses. This is separate from our aggregate analytics database; we cannot claim that network requests never expose an IP address to a hosting provider. See Vercel’s privacy policy and Neon’s privacy policy.

The homepage embeds a demo from YouTube. Loading that player contacts Google and can set cookies under Google’s own policies. The player is served from youtube-nocookie.com. The typefaces are loaded from Google Fonts.
